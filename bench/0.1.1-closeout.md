# 0.1.1 closeout

Scope: the 0.1.0 writer and quality bench only. Anki plumbing and all 0.2.0 work belong to a separate chat and separate worktrees. PR #1 remains unmerged until the user approves merging.

## Decisions and implementation

The four core kinds remain enabled; trial kinds remain experimental and off by default. The per-node cap stays at two, with one preferred when a sibling would repeat the same retrieval demand. Soft word targets are now 30 front / 15 back, without sacrificing necessary assumptions.

Writer guidance now requires complete premises, explicit assumptions and standpoint, checked numerical examples, supported explanations and accurate Extra fields. It forbids defining or paraphrasing the answer on the front. Instruction-contract tests protect those requirements, but do not prove model outputs are correct. Deterministic validation is not a semantic verifier.

The runner now supports `--max-calls` across concurrent batches and retries, and records the writer version and CLI-call count. Automated summaries use an explicit `--scores sol` flag, read `scores.sol.json` and write `summary.sol.md`. Human files remain untouched. Incomplete generation, no generated cards and unapproved skips cannot produce a passing summary.

Multiline code support from PR #1 is retained, including escaping and indentation. The minimal preview still requires matching fence lengths; accepting longer closing fences is a deferred compatibility nit.

# Anki Bridge 0.6.1 verification

This patch is for the private personal trial. It does not publish a GitHub Release or make the repository public.

- The bridge checks the Anki URL and profile shown in the view before sending cards or updating a note type. AnkiConnect still does not make a profile check and a write atomic. Leave the paired profile open until the action finishes.
- A key entered for one URL does not follow an untouched field when a refresh brings in a different URL. Changing the saved URL also clears the saved key unless you supply a new one.
- Refreshes preserve unrelated edits. Sent history starts closed and only renders its cards when opened. The Anki formatting preview uses the delivery renderer for Front, Back and Extra. It does not reproduce Anki's templates, CSS or MathJax output. The writer checks the delivery renderer and explicit TeX delimiters before accepting a draft; it does not validate the mathematics.
- The patch keeps state schema 4. If you upgrade an older schema, the bridge saves the original bytes in `state.vN.bak` beside `state.json` before writing the upgrade. Keep both files private. They may contain your API key. If a different backup already exists, move it someplace safe before retrying the upgrade.

## Note format

`LearnHarness Basic` uses six fixed field names: `Front`, `Back`, `Extra`, `Source`, `LH_ID`, and `LH_Node`. Keep `Front` first for Anki's duplicate check. `LH_ID` is the raw card UUID. `LH_Node` is the HTML-escaped graph node ID, or empty for hand-written cards. The two IDs are not displayed in the standard card template. Leave both intact for recovery and tracing.

The CSS ownership marker is separate from the style revision. Existing 0.6.0 styles still count as owned and do not need an update before sending. New notes have the `learnharness` and card-kind tags. They no longer include a session-title tag. The original session title stays in `Source`; existing notes and tags are unchanged.

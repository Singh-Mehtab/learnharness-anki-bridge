# Anki Bridge 0.6.0 candidate verification

This version packages the existing plugin. It does not add a feature or change the state schema.

## Passed

- `npm test`: 201 tests. The new packaging tests check the exact archive contents, a clean extraction and installation, preservation of `data/` on code replacement, and rejection of mismatched versions and symlinked build inputs before rebuilding.
- `npm run typecheck`, `npm run package:plugin`, `unzip -t anki-bridge-v0.6.0.zip` and `bash tests/tag-version.test.sh`.
- Fresh install of the actual zip using the bundled LearnHarness 0.6.1 server and a separate Chromium browser. The app found the plugin disabled, enabled it and loaded the settings and sidebar view. A manually created scratch draft rendered maths and fenced code. Disabling blocked plugin calls, and re-enabling retained the draft.
- Upgrade from code built from merged 0.5.0. With LearnHarness stopped, the test replaced only `dist/` using the extracted 0.6.0 archive. After restart the plugin stayed enabled, the scratch draft and settings matched, and `data/state.json` was byte-for-byte identical.
- Final regression suite covers older state migrations, interrupted generation, uncertain sends and reconciliation, profile and endpoint checks, and cleanup of late operations. These use test hosts or a local AnkiConnect stub.

The browser checks ran the installed app's standalone server in Node mode with a scratch home, data and empty auth file. They did not launch the native Electron window. No real LearnHarness records, live models or Anki profiles were used. A separate source checkout in Next.js webpack development mode reported `nativeRequire is not a function` on activation for both 0.5.0 and 0.6.0. The bundled server activated both.

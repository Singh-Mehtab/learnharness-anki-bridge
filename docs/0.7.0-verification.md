# Anki Bridge 0.7.0 verification

Version 0.7.0 redesigns the interface to fix the 18 issues filed after 0.6.1 (#11 to #28). State stays at schema 4. Two optional settings (`tagTemplate`, `systemTags`) and an optional `hidden` flag on finished generations are new; older versions ignore them.

## Passed

- `npm test`: 210 tests. The rewritten interface tests cover the idea list (labels, menus, selection limits, stale reads, backfill intent), writing (estimate dialog, stale selections, cancel, retry, dismiss, readable provider errors, polling), session scoping and flags, settings (key handling, connection messages, profile confirmation, note type repairs, tags) and review (columns, editing through refreshes, approval, deck and tag checks, sending, recovery menu, hand-written cards). New backend tests cover tag templates, explicit tags, turning off the learnharness tags and dismissing finished generations.
- `npm run typecheck` and `npm run build`.
- Screenshot pass in the installed LearnHarness 0.6.1 server (Node mode, scratch home, data and auth file) with Chromium, in dark and light themes. Data was synthetic: two sessions, eight ideas, three cards and one flag. A local fake AnkiConnect served decks and accepted notes. Checked screens: all three steps, editing, the More menu, hand-written card dialog, sending with and without a deck, sent history, the flag dialog, Make cards, Anki closed (page banner and settings message), the estimate dialog and a failed run.
- One send went through the fake AnkiConnect with a template tag. The stub logged the deck `Year 3::Nuclear and Particle Physics 1` and the tags `Year_3::Nuclear_and_Particle_Physics_1::Lecture_01`, `learnharness` and `learnharness::kind::why`.
- A second pass took the README screenshots after the send bar was widened so full deck paths fit. The deck field kept the sent deck after the send and after a reload.
- Fixes after council round 1, each with a test that fails without the fix: a cleared deck stays cleared through errors and background refreshes; tags typed for one send reset to the template afterwards; a background refresh keeps focus and the caret in a card editor; the editor turns read-only while a save is in flight; a refresh that changes the saved address drops a key typed for the old one; a tag change made during another save is saved afterwards; first pairing loads deck suggestions; the connection check runs outside the backend writer lock, so approving works while Anki is slow; the progress panel shows only the running run, or else the latest result until dismissed. A third screenshot pass checked sending with a cleared deck (twice), the sent state and editing. The stub logged the typed tags `YEAR_3::NPP1::Lecture_01` and `extra` plus the learnharness tags.
- Fixes after council round 2, each with a test that fails without the fix: a connection check hides the key it used even if the saved key changes while it runs; deck and tags are locked while a send runs; switching profiles recounts which ideas are in Anki and stops offering the other profile's decks; a refresh asked for during a read gets a newer read; a hand-written card counts as an action, so an older background read can't hide it; the run summary counts ideas that got cards; a deck name containing `$&` stays literal in tags; a cleared typed key is explained under the address. The Write cards dialog now lists what goes to the model, and the README privacy section says that an excerpt of the source reply is sent for every idea, flagged or not. The edit, send and dialog screenshots were retaken.
- To see the estimate dialog and the failed-run panel, the scratch auth file held a deliberately invalid Anthropic key. Starting one run made a single request, which Anthropic rejected with HTTP 401. No real model output, account or quota was used.

## Not tested

- The native desktop window, keyboard shortcuts and Show in Anki in the real app.
- The card-quality benchmark remains open before any public release.

# Anki Bridge 0.7.1 verification

Version 0.7.1 fixes the issues filed after the user's first real run of 0.7.0 (#30 to #33) and two gaps left open in #17 and #19. State stays at schema 4, with no new settings. Issue #34 (which cards the writer makes) is not part of this version. It needs a design discussion and changes the writer, so it is planned for 0.7.2.

## Changes

- #30: deck, tag and other plugin inputs turn off font ligatures. LearnHarness uses JetBrains Mono for interface text. Its `::` ligature (`colon_colon.liga`) has a 600-unit advance and a left side bearing of -303, so half its ink sits in the previous character cell. Checked with fontTools on the font file bundled in LearnHarness 0.6.1. When an input clips that ink, the first colon disappears, as in the issue's screenshot.
- #31: the tags field suggests tags from the open Anki profile as you type. The connection check now also calls AnkiConnect `getTags`. If that call fails, decks still load and tag suggestions stay empty.
- #28 (remaining part): the template's `{deck}` takes the casing already in the collection, level by level. With `YEAR_3::…` tags in Anki, `Year 3::NPP1` becomes `YEAR_3::NPP1`. Anki already treats tags that differ only in case as the same tag. This change makes the preview show the casing Anki will use.
- #32: a successful send shows a green panel with the card count, deck and tags, plus Show in Anki and Dismiss. It stays until the next action or Dismiss. The check mark animates only when reduced motion is off. A partial send still reports which cards failed. With nothing left to review, the empty state says "Nothing left to review."
- #33: after Flag or Save note, the dialog says what was saved ("Flagged.", "Flagged with your note.", "Note saved.", "Note removed." or "Saved.") with the idea count, then closes after 1.5 seconds. Close still closes it at once.
- #17 (remaining part): a flagged idea with no cards shows Flagged and No cards.
- #19 (remaining part): only the newest deck lookup can fill the suggestions. An older lookup that finishes last is ignored.
- Recall's description in step 2 and the README said it states a fact, definition or formula. The writer prompt asks for a new example or question where the idea applies. The description now says that. Changing what Recall produces is part of #34.

## Passed

- `npm test`: 224 tests. New or changed tests cover the ligature rule, `getTags` in the connection check and its failure path, tag casing, tag suggestions, the tags field in the page, the send confirmation panel, the flag dialog closing after a flag or a note, the No cards badge on a flagged idea and stale deck lookups. The badge and lookup tests fail when their fixes are removed.
- `npm run typecheck` and `npm run build`.
- Browser pass with the LearnHarness 0.6.1 server bundled in the installed app, in Chromium with the dark theme. Scratch home, data and auth file, synthetic sessions, and a fake AnkiConnect that serves decks and tags. Checked: the template filled `YEAR_3::Nuclear_and_Particle_Physics_1::Lecture_01` from the stub's tags, typing `… ph` offered `physics`, the send panel appeared with the deck and tag, and the flag dialog showed "Flagged with your note. 5 ideas from this reply." and closed by itself. The README hero screenshot was retaken from this setup.

## Not tested

- The #30 fix in the native desktop window. Headless Chromium and WebKit rendered `3A::N` correctly with and without the fix, so the bug did not reproduce there. Whether it is gone in the desktop app needs a check on the user's machine.
- The tag suggestion popup itself. Headless browsers don't draw the native suggestion list. The tests check the suggested values.
- `getTags` against real AnkiConnect, and delivery to a real Anki profile in this version.
- Real model output. This version doesn't change the writer prompt.

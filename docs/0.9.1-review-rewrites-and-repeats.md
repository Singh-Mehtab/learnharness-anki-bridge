# Rewrite drafts and catch earlier repeats

An idea's graph ID tells us where a card came from. It doesn't tell us what the card asks the learner to recall. A fact can turn up in a different lesson under a different graph ID, and a Basic card can ask for the same answer as a cloze.

## Regenerate one draft

- Review offers **Regenerate** on an unsent draft. The user can add a short instruction for that card. The writer starts with the current draft, including saved edits, and its source. It sees the node's other cards but doesn't treat the original as a duplicate.
- Each request writes at most one replacement. The user can queue another while the first runs. The original stays in Review and can't be sent while the request is queued, running, or awaiting a decision. Review shows both versions and lets the user accept the replacement or keep the original. If the rewrite fails, use Keep original to clear the request and make the original sendable again. Sent cards and cards with an unresolved delivery cannot be regenerated.
- Accepting a replacement updates the unsent draft. It never edits a note in Anki. An accepted rewrite needs approval before sending. Reject stale actions if the draft or request has changed since the user saw it.

## Compare against earlier cards

- Search the bridge's own eligible cards across decks. Include unsent drafts and sent cards, excluding notes known to be missing from Anki and cards dropped in Review. Use the bridge's recorded presence. This feature doesn't scan the Anki collection for cards the bridge didn't write.
- Rank earlier cards by local text similarity. Give the writer up to three relevant matches per idea, subject to the prompt budget. A match may be from an unrelated graph node. Neither this lookup nor the check after generation adds a model call.
- If a candidate asks for the same recall task and answer, the writer can skip the draft. Review shows what it skipped and which card covers it. **Write anyway** makes one focused request and bypasses the earlier-card skip for that request only. A possible repeat should still be drafted, and the local check can still flag it.
- If the match is uncertain, keep the draft and flag it. Review lets the user compare it with the earlier card. Different recall directions, units that matter to the answer, or a distinct task in another course can justify keeping both.
- Check completed drafts locally for close matches the writer missed. This check only flags. Repeat flags don't require a decision before sending, but the send confirmation counts them.
- Validate the writer's repeat references against the candidate IDs it saw for that idea. Existing same-node and within-run checks still apply. Regenerated replacements get the earlier-card check too, without comparing the replacement to its own original. A repeat verdict must never remove the original draft.

## Verification

Use synthetic fixtures for the writer output, queue and delivery races, Review decisions, and cross-deck matching. Calibrate the local threshold read-only on stored bridge cards, checking a known cross-lecture Basic/cloze repeat and nearby distinct cards. Keep private card text out of this repo. In the read-only calibration, the backstop flagged one of 3,741 pairs across 87 cards at its 0.72 threshold. That was the known repeat, and each source ranked the other card first. This checks that example, not general recall. No live model bench was run.

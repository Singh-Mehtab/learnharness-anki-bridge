# Graph identity evidence for 0.5.0

Tested on 2026-11-18 against LearnHarness v0.6.1, commit `cb25c8e49b85eed9e78315584731cad73a0118a6`.

## Result

Use exact proposition node IDs for coverage. Do not resolve old IDs through `aliases`.

A linked reencounter appends another ledger line under the existing node ID. It does not create a second graph node and then redirect it. The graph reader combines those lines. Aliases contain phrasings supplied by extraction, including later statements. They are not an ID migration history.

Deletion followed by recreation produces a fresh ID, even for identical text. Coverage on the deleted ID must remain historical and show a missing source. It must not silently cover the recreated node.

## Experiment

A standalone Node script exercised the actual core merger, filesystem graph store, graph deletion and plugin learning facade. It used synthetic sessions and an isolated `LH_DATA_DIR`. It fixed random bytes and time inside its process to make the captured results reproducible, then restored both.

All 14 cases passed on two worker runs and an independent parent rerun. The first two captured results matched after excluding their unique scratch data-directory paths.

| Case | Observed result |
|---|---|
| Create a proposition | The store assigns a fresh `n_` ID. The extraction-local proposition ID is not the graph ID. Initial aliases are copied. |
| Link a reencounter from another session | Existing ID, name, statement and creation time stay fixed. Provenance unions. The later statement and supplied aliases join aliases without duplicate phrasings. |
| Read through the plugin learning facade | `learning.graph()` equals `graphSnapshot(...)`. `nodeSessions` includes both sessions. `readGraphFile("nodes.jsonl")` returns raw ledger lines instead. |
| Reuse an existing graph ID as an extraction-local ID, without a link verdict | A different graph node is created. |
| Use one existing ID as a local ID linked to another existing node | Both original nodes remain. No existing-node merge or ID rewrite occurs. |
| Link to an unknown ID | A fresh node is created. The unknown target and local ID are not automatically added to aliases. |
| Supply ID-shaped alias text | The text is accepted as a phrasing. A nonexistent `linkTo` matching that alias still creates a fresh node. |
| Delete a proposition | Every ledger line under its ID disappears. Repeating deletion returns null. Unrelated alias text is unchanged. |
| Recreate a deleted proposition with its old ID as local ID and link target | A fresh ID is assigned. No old-ID alias is added. |
| Create a multi-premise chain | The plugin snapshot has an `arg_` implication node with empty aliases. The derived proposition list does not contain it. |
| Reassert the same chain from another session | Its argument ID remains and provenance unions. |
| Link a proposition to an `arg_` ID | It is not an existing proposition target. A fresh proposition is created. |
| Delete and reassert an argument | Deletion preserves its proposition members. Reassertion gets a fresh `arg_` ID without an old-ID alias. |
| Simplify a multi-premise chain to a single-premise chain | The old implication node disappears. Proposition aliases do not change. The new chain is an arrow, not an implication node. |

For example, initial aliases `["Initial phrasing"]`, a linked statement `"Later statement"` and supplied aliases `["Later phrasing", "Initial phrasing"]` produce `["Initial phrasing", "Later statement", "Later phrasing"]`. Neither the later name nor its local proposition ID is added. The raw second ledger line still contains only its supplied aliases.

## Source evidence and limits

These paths and line numbers refer to the pinned LearnHarness commit.

- `src/core/graph.ts:79-87,149-212` assigns IDs and resolves link-or-create using existing proposition IDs.
- `src/core/graph.ts:395-442` combines node lines by ID. The first line defines identity fields; later phrasings and provenance join them.
- `src/core/contracts/graph.ts:113-132,246-269` defines stable graph IDs, phrasing aliases and local-to-existing-node link verdicts.
- `src/core/graph.ts:225-276,445-568` handles chain identity, simplification and plugin snapshots.
- `src/core/graph-deletion.ts:297-344` deletes proposition and argument traces.
- `src/server/plugin-learning.ts:17-40` implements the tested learning facade. `src/server/plugins.ts:43-45,74-75` supplies it to plugin services.
- `src/core/ports.ts:149-163` and `src/store/graph.ts:207-233` expose generic ledger replacement. Inspected callers use it for deletion and chain simplification.
- `src/server/graph.ts:89-125` and `app/api/graph/nodes/[id]/route.ts:21-28` provide the deletion route and extraction-running gate.

No dedicated existing-node-to-existing-node merge or redirect API was found in the inspected graph writers and HTTP routes. This is a bounded source inspection, not proof that no other operation can ever rewrite IDs.

The experiment did not run the full plugin host, browser, HTTP deletion gates or an extraction model. It proves the behavior of explicit merger inputs and the plugin graph facade, not whether a model will choose the correct link verdict. It made no Anki or model calls and did not read real application data or credentials. The reference checkout remained clean.

## Local reproduction

The temporary experiment directory is `/tmp/anki-bridge-050-graph-identity.AKtMMG`. It is not a repository dependency and may disappear when temporary files are cleaned.

```sh
node /tmp/anki-bridge-050-graph-identity.AKtMMG/graph-identity.mjs
```

The script checks the source commit at `/tmp/lh-src/repo`, sets `LH_DATA_DIR` before importing storage, and creates a new data directory under its own scratch directory for each invocation. Node v26.13.1 ran the TypeScript source through native type stripping without dependencies or package installation.

Local evidence includes `graph-identity.mjs`, `run.log`, `rerun.log`, `parent-rerun.log`, `results-first.json`, `results.json`, `reproducibility.log` and `writer-search.txt`. Each run ended with `RESULT 14/14 passed`. Captures include raw ledgers, derived graphs and plugin snapshots at six checkpoints. Only this summary is committed; the script and detailed synthetic captures remain temporary.

# 0.5.0 verification

This development branch implements the [reviewed coverage design](0.5.0-coverage-design.md) from PR #6 on top of 0.4.0. The [graph identity results](0.5.0-graph-identity.md) establish the exact-ID rule separately.

## Automated checks

All 187 tests passed, along with `npm run typecheck` and `npm run build`. The tests cover saved destination and source state, dismissal and restore, migrations from schemas 1 through 3, interrupted work, and the shared writer fence. Coverage changes cannot revive an estimate after dismiss and restore. Fake workers test confirmation, retry after restart, and rejection when a backfill target gains a card. DOM tests cover search, selection changes, late replies, session handoff and the 1,000-node limit.

## Scratch LearnHarness

Nine browser checks passed on the built 0.5.0 plugin in LearnHarness v0.6.1. The host ran on loopback with isolated data, home and auth paths. The fixture used seven synthetic propositions and a schema 3 state file with flags and card history. The installed frontend matched the built bundle.

- Both pickers loaded without a configured model or live Anki connection. Sent, waiting, changed and deleted-note labels reflected saved records.
- Missing history stayed nonselectable. An old ID in alias text did not cover a recreated proposition.
- Dismiss and restore worked in the picker. Dismissals survived disable and re-enable, and migration to schema 4 preserved card history.
- The no-cards filter and bulk selection agreed, including dropped-only history. Search removed hidden selections, and refresh did not restore a cleared selection.
- A simulated graph RPC failure kept the previous rows visible but stale. Selection stayed disabled until a successful refresh.
- The session selected eligible flagged ideas, including sent ones, but excluded a dismissed idea. Bulk selection passed the intended nodes to the drafting panel.
- No browser exceptions occurred. The run made no model or Anki calls.

The browser run checked selection and handoff, not confirmed generation. Automated integration tests use a fake worker for that path. A live model, live Anki delivery of generated cards, and packaged Electron were not tested in 0.5.0. Full card-quality validation remains deferred until before public release.
